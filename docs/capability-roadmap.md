# Cocos MCP 完整能力实施方案

## 1. 目标与范围

目标是让 Agent 在明确的 Creator 版本、工程、场景和运行时上下文内，完成可预览、可执行、可校验、可恢复的开发任务。不能把全部原生 API 机械包装后称为“完整支持”。

本方案中的能力 ID 起初均为建议设计；当前已落地入口与未完成项以 [阶段实现说明](roadmap-implementation.md) 为准，未列入已实现清单的建议接口仍不可调用。实现前须检查当前安装的 Creator 消息、类型声明和引擎源码。第一条完整适配线为 Creator 3.8.8；Creator 2.4.x 和其他 3.x 版本分别建立兼容矩阵，不自动继承验证状态。

现有基础继续复用：

- `packages/capability-catalog`：能力 Schema、支持范围、独立服务工具、覆盖统计和验收证据。
- `packages/application` / `packages/editor-bridge`：目标路由、工程队列、operationId、revision、结果记录与失败语义。
- `packages/creator3-adapter` / `extensions/creator3`：Editor/AssetDB 适配、原生消息与 scene 脚本。
- `packages/runtime3-bridge`：受控运行时对象、资源生命周期及实际帧验证。
- `packages/native-adapters`：编辑器发现、构建与后续设备工具；平台命令必须限定目标、参数和产物目录。

工程约束：新资源先 `asset.location`，复用已有类型目录；已有资源移动只走 AssetDB。运行记录、截图、缓存和构建产物只写 `.codex-work/`。不自动保存脏场景，不执行任意 eval，不跨工程操作，不把资源 UUID 不变当作字符串加载路径必然正确。

## 2. 实施顺序与阶段出口

| 阶段 | 工作包 | 为什么先做 | 阶段出口 |
|---|---|---|---|
| P0 真实清单 | 本次的覆盖统计、独立工具、验证证据、不可执行入口过滤 | 后续必须能准确表达完成与缺口 | 单元/协议回归通过；源码变化自动使旧测试证据失效 |
| P1 场景与 UI | 声明式 UI、布局检查、资源模板、基础纹理与字体 | 最常见生产任务；复用已有节点/资源接口 | 一份 JSON 生成可运行 UI，保存重开仍一致，失败只补偿本次操作 |
| P2 内容制作 | 动画剪辑与控制、模型、粒子、TileMap、相机灯光 | 将“能改属性”升级为可完成制作任务 | 每方向至少一个端到端样例和一个错误恢复样例 |
| P3 运行与交互 | 物理、输入、调度、Bundle、媒体生命周期 | 需要真实运行帧、事件与资源拥有关系 | 预览中可验证行为，断开/切场景后无工具遗留资源 |
| P4 高级图形 | 动画图、Spine、Terrain、探针、渲染管线、底层图形 | 版本差异大，依赖前面稳定资产和验证设施 | 精确版本适配、源码校验和目标后端验证；不支持项明确拒绝 |
| P5 平台交付 | 设备、原生桥、热更新、XR、引擎定制 | 依赖 SDK、设备和构建体系 | 按目标平台分别验收，不用 Web 成功替代真机结果 |
| 横向持续 | 自定义能力包、文档查询、性能和兼容性回归 | 避免专用接口散乱和信息过期 | 每个新增包都能被发现、说明依赖、限制权限、记录验收 |

每阶段按“只读查询 → 规划预览 → 单项修改 → 批量组合 → 保存重开/运行 → 恢复”逐步交付。下游阶段可以先做只读接口，但不得绕过上游的身份、引用与生命周期约束。

## 3. UI 自动搭建（F18–F20）

**第一批交付**：实现 `ui.build` 的最小完整闭环，覆盖 Canvas、容器、Sprite、Label、Button、Layout、Widget、ScrollView，随后扩展 Toggle、EditBox、PageView、Mask 和 RichText。

- 输入：版本化 UI 文档、目标 parentId、稳定逻辑节点 key、节点/组件/属性、资源 UUID、布局约束、事件声明。限制层数、节点数、字符串长度和单批操作量。
- 输出：逻辑 key 到实际节点/组件 UUID 的映射、逐项执行结果、资源实际路径、需保存标记、布局/引用诊断。
- 建议接口：`ui.plan`、`ui.build`、`ui.inspect_layout`、`ui.validate_interaction`。第一版只创建；更新既有树另做 `ui.diff/apply`，不能用全量删除重建冒充更新。
- 实现：先把声明树转成已验证的节点/组件操作；遇到无效类型、错误资源或不支持属性，在写入前拒绝。UITransform 尺寸、锚点、Layout 和 Widget 按实际原生属性适配。
- 事件绑定只允许明确组件、方法和参数，不允许任意 JS；运行时点击验证与持久化事件编辑分开。
- 补偿：记录本次创建的节点和资源；仅回收工具独占且未被外部引用的对象。遇到用户并发修改不全局 undo。
- 验收：不同画布尺寸下无越界/非预期重叠；按钮实际触发正确回调；滚动范围可达；保存重开 UUID 映射和事件引用有效；构建到第 N 个节点失败能报告并处理部分完成。

## 4. 动画、动画图与骨骼（F23–F26）

拆成三条适配线，不在一个通用参数对象里混装。

1. **剪辑编辑**：建议 `animation.clip.inspect/create/patch/sample`。支持轨道目标路径、值类型、关键帧时间、插值、事件和循环。先实现变换/透明度等基础轨道，再增加复杂曲线。写前验证时间排序、重复帧、目标存在和类型；保存使用引擎序列化/AssetDB，不能凭猜测拼内部资源格式。
2. **运行控制**：`runtime.animation.play/pause/seek/state/blend`。返回实际播放状态与采样姿态；避免把方法返回成功当作画面已变化。工具调试要记录原播放状态并提供明确恢复策略。
3. **高级动画**：`animation.graph.inspect/plan/apply`，再扩展 Spine/DragonBones 的皮肤、轨道、插槽和混合。先检查 Creator 模块、资源格式和运行库版本；禁止跨版本静默转换。第三方资源工具及许可条件须单独确认。

验收：保存重开关键帧与事件一致；采样位置符合容差；一次播放不重复触发事件；CrossFade 可观测；图状态转换与条件一致；缺骨骼/插槽、非法帧和不匹配资源版本均给出具体诊断。动画图、Spine、DragonBones 分别记证据，不相互代替。

## 5. 特效与场景制作（F27–F30）

- **粒子**：`particle.inspect/plan/apply` 与运行时 `play/stop/state/capture`。按 2D/3D 分别声明模块；覆盖发射、生命周期、颜色/尺寸曲线、速度、形状、纹理动画和拖尾。校验曲线值域与资源类型，控制粒子数量。确定性种子仅在目标版本确有支持时开放。
- **TileMap**：图层/对象组查询、区域瓦片编辑、碰撞信息检查。批量编辑使用有界矩形和差异补丁，保留原图块索引；不整图覆盖外部修改。
- **Terrain**：高度、权重、图层查询先行；刷写采用有限区域、分辨率和备份守卫。独立处理坐标映射、接缝与量化误差，不能复用 TileMap 的数据模型。
- **相机与环境**：投影、视口、曝光、天空盒、雾等提供语义化 Schema，保留已有组件编辑入口。多相机渲染顺序与可见层必须一起检查。
- **灯光与探针**：灯光参数先行，Lightmap/探针烘焙后置为可查询状态的任务。先发现原生烘焙能力与平台支持，再开放执行；不能用渲染截图假装完成烘焙。

验收：粒子真实帧可见、停止/恢复可验证；瓦片局部修改无旁区变化；Terrain 边界不撕裂；多相机目标纹理正确；烘焙产物存在、绑定有效、重开工程仍可加载。失败记录阶段和本次产物，不自动清理用户原有贴图。

## 6. 资源制作与模型（F16、F17、F21）

先统一“源资源、导入配置、子资源、实际使用者”的读模型，再做写工具。

- **纹理**：`texture.inspect/plan_import/apply_import`，覆盖采样、Mipmap、颜色空间、压缩和平台覆盖；根据 Creator 导入器实际字段映射，不虚构跨版本通用配置。
- **图集**：`atlas.inspect/plan/build/validate`，明确静态图集资源和动态合图运行状态的区别；规划打包范围、尺寸、留白和 SpriteFrame 引用。
- **字体**：查询字体类型与字形范围，验证 Label 引用和字符缺失。位图字体及纹理按依赖组处理，不能分别搬移。
- **模型**：扩展现有 `geometry.create`；增加子网格、材质槽、蒙皮、骨骼、Morph、LOD 检查与编辑。外部 glTF 文件作为依赖组导入；不得只移动主文件。
- **批处理**：先输出影响资源、重新导入成本和冲突；保留 UUID/meta，结果逐项读回，不把首项成功当成整批成功。

验收：目标平台导入设置实际生效；SpriteFrame 裁边/九宫格正确；图集重建引用有效；字体样例缺字可诊断；蒙皮无丢骨骼；LOD 切换可观测；失败可恢复精确配置且不损伤原始资源。

## 7. 物理、输入与调度（F33、F34、F36、F37）

- 2D/3D 各建查询、配置、运行查询三个层面；先获取实际启用后端和模块，再决定可用形状、关节、约束与查询。
- 建议 `physics2d/physics3d.inspect/plan/apply`；运行时补充 `raycast/overlap/step/state`。参数统一说明坐标空间、单位、层掩码、是否包含触发器与结果上限。
- 刚体写入要区分编辑器配置和运行时速度/力；不允许模糊的“重置全部物理世界”。
- `runtime.input.dispatch/sequence` 只对指定预览实例模拟事件，区分 Canvas 坐标、屏幕坐标与 UI 命中。不能扩展为任意操作系统键鼠控制。
- `runtime.scheduler.inspect/pause/resume` 和 Tween/Action 适配要跟踪工具创建的任务；取消默认只取消工具拥有的对象。

验收：射线命中对象与距离正确；接触/触发事件次数可核验；固定步进具有可解释结果；输入穿透、遮挡和焦点测试通过；暂停恢复不重复调度；运行时断开后无工具任务泄漏。不同物理后端单独记录限制。

## 8. Bundle、运行时资源与媒体（F35、F38）

- `runtime.asset.load/preload/inspect/release` 采用资源句柄和拥有关系，禁止任意释放游戏已有共享资源。
- `runtime.bundle.inspect/load/unload` 返回依赖和工具持有计数；卸载前检查当前场景、组件与其他句柄引用。远程资源必须明确目标地址、大小限制、超时与缓存位置。
- 区分“请求已提交”“资源加载完成”“已绑定并参与绘制”。失败返回加载阶段和可恢复原因。
- 音频、VideoPlayer、WebView 各自提供状态、播放/暂停/定位和错误查询。平台权限、自动播放限制与不支持平台必须直接报告。

验收：重复加载不会产生无法回收的句柄；加载取消/断开能收敛；共享纹理仍被使用时不能误释放；Bundle 卸载不破坏当前场景；媒体进度实际变化，结束事件正确；权限拒绝能得到明确结果。

## 9. 图形、平台、XR 与引擎定制（F31、F32、F40–F42）

这是后置的受控能力，不能通过放开 `runtime.invoke` 私有成员代替适配。

- **图形后端发现**：先提供 GPU/后端/扩展/格式支持查询，再考虑 Buffer、Texture、Framebuffer 等专用句柄。分配设置内存预算，依赖对象按顺序释放。
- **自定义管线**：建议 `render_pipeline.inspect/plan/install/validate`。按版本隔离注册代码；先在独立样例验证后再接入工程；保存旧配置与恢复入口。Shader 原生编译通过不等于自定义管线已渲染正确。
- **平台桥**：JSB、Java、Objective-C、ArkTS 分适配器；公开明确的方法签名和可用平台，不能开放任意命令或任意类反射。
- **XR**：发现模块和设备能力后开放姿态、输入与空间配置；模拟器与真实设备分开标记。没有相应模块时不提供虚假的可执行工具。
- **引擎定制**：源码只读定位和模块方案先行；源码修改、绑定生成与构建作为独立工作流，明确工具链、版本和回滚目标，不覆盖用户已有定制引擎。

验收：资源预算/失效句柄/释放顺序边界通过；管线恢复后原场景正常；平台回调和错误可往返验证；XR 真机输入与姿态校验；定制引擎版本指纹可追溯。GPU 驱动日志、不同后端和真机结果分别标记。

## 10. 发布、真机与热更新（F47–F50）

已有构建任务保留，后续增加构建方案、平台适配和设备流程，不能从零重新做一个重复构建器。

- 构建方案：查询已安装平台、配置 diff、场景/Bundle/裁剪规划、构建前检查。平台工具链缺失时在任务开始前报告。
- 产物：核对目标平台、架构、入口文件、清单与文件指纹；“进程退出 0”“目录存在”“包可安装运行”是三个验证层级。
- 设备：`device.list`、目标身份确认、安装、启动、日志、截图和崩溃收集；所有操作要求明确设备 ID，不默认选择第一台设备。
- 热更新：清单生成、差异包、哈希核对、版本策略、失败恢复和回滚；先在测试端点完成。签名、上传、公开发布和生产地址变更保持单独授权边界。
- 服务重启或构建超时，优先读取任务和产物，不能盲目重试引发重复构建或安装。

验收：Web 与各原生平台分别构建、安装和启动；错误 SDK/架构能提前诊断；取消后进程和锁回收；断网、损坏包、更新中断和回滚测试完成；不得用单一平台结果标记 F48/F49 整体完成。

## 11. 自定义扩展、文档与知识（F53、F54）

- 能力包：声明包 ID/版本、支持 Creator 范围、依赖、参数 Schema、风险、权限和验证器。注册时检查重复 ID、非法 Schema、依赖环和不可用平台。
- 分发保持受控：只加载用户明确安装的包；不从项目资源字符串自动执行代码。不用通用“运行脚本”掩盖权限范围。
- 文档查询：以本地版本、模块开关、API 来源与源码路径为过滤条件；返回来源和适用条件。扫描到的候选 API 先进入候选库，不能直接标记已实现。
- 错误与迁移：将结构化错误码连到版本文档和已验证案例；跨版本迁移必须给出差异计划与不兼容项，不能静默替换组件类型。

验收：无效包不会污染现有注册表；卸载后不留下运行时句柄；同名能力冲突被拒绝；查询不会把其他版本结果冒充当前接口；离线、缺模块和来源失效时能明确降级。

## 12. 统一完成标准与交付清单

每个工作包交付：能力定义、版本适配、错误与恢复语义、最小样例、回归测试、使用说明、证据及明确未覆盖项。至少包含以下检查：

1. Schema：非法字段、边界大小、错误类型和无效版本在副作用前拒绝。
2. 工程边界：路径、符号链接、目标实例、revision/源码哈希、名称冲突检查。
3. 生命周期：谁创建、谁引用、谁能释放；场景切换、断线和重复请求行为明确。
4. 持久化：AssetDB 读回、UUID 与子资源引用、保存重开验证。
5. 实际运行：目标帧、事件、像素、播放状态或设备结果；不能只看函数返回值。
6. 失败恢复：部分完成列表、pending 意图、补偿边界与不应重复执行的状态。
7. 清单：只暴露已实现入口；运行依赖缺失时显示不可用；源码测试与原生/设备验收分级。

模块标为 implemented 的条件：完整 scope 经显式审查，验收项引用真实入口，并有匹配当前源码的编辑器/运行时/设备证据。部分对象或入口完成时仍为 partial。无代码的方向保持 planned，不能为了提高覆盖率添加空壳工具。

P1 已落地 UI 规划/创建/静态检查、纹理导入守卫与字体查询；P2 已落地基础变换剪辑创建/查询/曲线采样，P3 已落地受控资源引用与 Bundle 查询。这些阶段均未完成全部出口验收。继续工作应先补 P1 保存重开、实际点击和多分辨率验证，再推进各阶段剩余项；P4 已有图形后端只读查询，P5 已有构建产物检查，完整平台交付尚未完成。

继续实施记录：已补 UI 字段 diff/apply 与四类控件、剪辑关键帧 patch/restore、动画运行控制、预览输入/尺寸、物理射线查询、音视频组件控制及 WebView 只读检查。完整边界见 [实施记录](roadmap-implementation.md)。P1–P3 仍为 partial，P4/P5 和横向扩展尚未完成，不把新增操作数等同于阶段完成度。

优化记录：已增加 2D/3D 粒子运行控制、图形设备与格式支持查询，补充新增 UI 控件静态校验及运行时断线收敛。以上入口需 Creator 3.8.8；模块仍按实际范围显示 partial，原生与设备验收不随源码测试自动升级。

P5 后续记录：已新增 cocos_build_artifacts，对成功任务进行入口、文件清单、SHA-256 和检查期间变化检测。设备安装、签名、热更新及真机运行仍无完成证据。详见阶段实施说明。
